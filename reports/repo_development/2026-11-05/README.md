## Changes

Catalogue index generation now supplies one canonical set of bytes to explicit
regeneration and read-only verification. `--check-indexes` reports missing or
stale indexes with a nonzero exit code and a regeneration command. It never
repairs a file as a side effect. The two workflows that previously regenerated
indexes before comparing them now invoke the read-only check. Catalogue tests
exercise regeneration only in temporary miniature repositories.

The coherence runner defaults to two workers and accepts only one or two.
Mocked CLI tests cover both accepted settings, the default, and rejection of
zero, three and four before any output or rendering. The course-numbering
workflow includes these tests in its fast check job. The two-process limit
across independent queues remains a coordinator responsibility.

The root README links the roadmap and maintained audit index. The index links
the October 15 coherence, pilot and offline narration records while preserving
dated limits. Architecture guidance now agrees with the existing manual-main
narration policy. Earlier reports and the catalogue's generated bytes remain
unchanged.
